# 情境關係（Context Map）

規則 DDD-3：跨情境整合只能透過已發布的事件或明確的介面，接收端用防腐層轉成自己的用語。

## 第一階段

只有一個業務情境：

| 業務情境 | 模組 | 負責什麼 |
|---|---|---|
| 看板管理（board-management） | `board-management/` | 看板、欄位、卡片的建立與變更；在製品上限；卡片移動歷程 |

沒有上游，也沒有下游。**DDD-3 在第一階段尚未實作**，因為沒有第二個情境可以整合。

## 第二階段（規劃，尚未實作）

加入「流程分析」情境。它是看板管理的下游：訂閱看板管理發布的事件，經過自己的防腐層轉成流程分析的用語，不直接引用看板管理的任何領域類別（由 `CONTEXTS_DO_NOT_SHARE_DOMAIN` 規則守住）。
